# 어떻게 동작하나

> 이 문서는 "왜 갑자기 터미널이 달라 보이는가"에 답합니다.
> 설치만 하실 거면 [README](../README.md)로 충분합니다.

## 한 줄 요약

터미널은 **하나의 프로그램이 아니라 4개 층**입니다. 이 리포는 그 4층을 전부 갈아끼웁니다.
PowerShell에 테마를 입히는 게 아닙니다.

```
┌─ 4. 폰트             MesloLGM Nerd Font   ← 글리프가 실제로 존재하는가
├─ 3. 프롬프트 생성기   oh-my-posh           ← 무슨 문자열을 뱉을까
├─ 2. 셸              PowerShell 7          ← 명령을 해석
└─ 1. 터미널 에뮬레이터  Windows Terminal     ← 그 문자열을 어떻게 그릴까
```

기본 Windows 환경은 이 스택이 `conhost.exe` + `powershell.exe 5.1` + `프롬프트 없음` + `기본 폰트`입니다.

## 핵심 원리: 셸은 색을 칠하지 않는다

프롬프트가 실제로 화면에 내보내는 바이트를 그대로 찍어보면 이렇습니다
(`ESC`는 0x1B, 눈에 보이게 치환한 것):

```
<ESC>[38;2;255;106;193m<ESC>[0m<ESC>[48;2;255;106;193m<ESC>[38;2;40;42;54m  <ESC>[0m
<ESC>[48;2;87;199;255m<ESC>[38;2;255;106;193m<ESC>[0m<ESC>[48;2;87;199;255m ~ <ESC>[0m
<ESC>[38;2;90;247;142m❯<ESC>[0m
```

읽는 법:

| 시퀀스 | 의미 | 값 |
|---|---|---|
| `<ESC>[38;2;R;G;Bm` | 앞으로 **글자색**은 RGB(R,G,B) | `255,106,193` = `#FF6AC1` |
| `<ESC>[48;2;R;G;Bm` | 앞으로 **배경색**은 RGB(R,G,B) | `87,199,255` = `#57C7FF` |
| `<ESC>[0m` | 서식 초기화 | |

이게 **ANSI 이스케이프 시퀀스**입니다. 셸은 색을 칠하지 않습니다.
"이 색으로 칠해줘"라는 주문서를 텍스트에 섞어 흘려보낼 뿐이고,
그 주문서를 해석해 실제 픽셀을 그리는 건 **창(터미널 에뮬레이터)** 입니다.

> 맥에서 Terminal.app을 iTerm2로 바꾸면 zsh는 그대로인데 화면이 확 달라지는 것과
> 정확히 같은 일입니다. **주문서가 아니라 화가를 바꾸는 것.**

이 분리 덕분에 실용적인 이점이 하나 생깁니다. 이 리포는 Git Bash 프로필도 같은 창에
등록하는데, 셸이 완전히 다른데도 배색·폰트·투명도가 동일하게 적용됩니다.
1층이 공유되기 때문입니다.

## 1층 — 터미널 에뮬레이터 (가장 큰 변화)

시작 메뉴의 "Windows PowerShell"은 `conhost.exe`라는 레거시 콘솔 호스트에서 열립니다.

"색이 구리다"고 느끼게 되는 그 남색 배경은 `#012456`으로, **레지스트리에 박힌
16색 고정 팔레트**의 일부입니다. conhost에는 "배색"이라는 개념 자체가 없어서,
바꾸려면 창 속성에서 16칸을 하나씩 수동으로 고쳐야 합니다. 여기에 더해:

- 투명도·블러 없음
- 탭·분할 없음
- 폰트 목록이 콘솔용으로 등록된 것만 노출 (Nerd Font가 목록에 안 뜨는 경우가 흔함)
- 글리프 폰트 폴백이 약해 없는 문자는 두부(□)로 렌더

Windows Terminal은 DirectWrite로 그리는 현대적 앱이라 **이름 붙인 배색을 통째로
갈아끼우고**(그래서 Snazzy ↔ Dracula를 드롭다운으로 전환), 아크릴 블러·탭·분할을
지원하며, 설치된 아무 폰트나 쓸 수 있습니다.

**가독성과 색이 바뀌는 결정적 원인은 이 1층 교체입니다.**

> 오해 주의: 최신 Windows 10의 conhost도 24비트 색 이스케이프 자체는 해석합니다.
> 문제는 "색을 못 낸다"가 아니라 **기본 팔레트가 그 남색이고, 배색을 통째로 바꿀
> 수단이 없으며, 폰트·투명도·탭이 막혀 있다**는 점입니다.

## 2층 — 셸

`powershell.exe` 5.1은 .NET Framework 기반으로 2016년에 사실상 동결됐습니다.
`pwsh` 7.x는 별개 제품이라 5.1과 나란히 설치되며, 최신 PSReadLine이 따라와
히스토리 예측 같은 입력 기능이 붙습니다.

다만 분명히 해둘 게 있습니다 — **외형과는 거의 무관합니다.**
색이 예뻐지는 것과 셸 버전은 별개입니다. 이 층은 조작감을 위한 교체입니다.

## 3층 — 프롬프트 생성기

PowerShell은 입력 줄을 그리기 직전에 **`prompt`라는 이름의 함수를 호출**하고,
그 반환값을 프롬프트로 씁니다.

`oh-my-posh init`이 하는 일은 딱 하나 — 그 `prompt` 함수를 자기 것으로 갈아끼웁니다.

```powershell
oh-my-posh init pwsh --config $OmpTheme | Invoke-Expression
```

이후 매 프롬프트마다 `oh-my-posh.exe`가 실행되어

1. JSON 설정을 읽고
2. 현재 경로·git 상태·node/python 버전·직전 명령 실행시간을 수집한 뒤
3. 위에서 본 이스케이프 범벅 문자열을 만들어 돌려줍니다.

그래서 테마가 JSON이고, 세그먼트를 자유롭게 조립할 수 있는 겁니다.
[`config/snazzy.omp.json`](../config/snazzy.omp.json)이 그 설정입니다.

## 4층 — 폰트 (장식이 아니라 필수)

프롬프트의 구분자 ``나 git 아이콘 ``은 유니코드 **사설 사용 영역**
(Private Use Area, U+E000–U+F8FF)에 있습니다. 표준이 아무것도 정의하지 않은,
폰트 제작자가 마음대로 쓰라고 비워둔 구역입니다.

| 글리프 | 코드포인트 | 용도 |
|---|---|---|
| `` | U+E0B0 | powerline 구분자 |
| `` | U+E0B6 | 왼쪽 반원 |
| `` | U+E718 | node.js |
| `❯` | U+276F | 프롬프트 화살표 (이건 표준 영역) |

일반 폰트에는 그 자리에 아무것도 없어서 **두부(□)** 로 나옵니다.
Nerd Font는 바로 그 구역에 아이콘 수천 개를 이식해둔 패치 폰트입니다.

폰트를 안 깔면 프롬프트가 네모 상자 행렬이 되고, **깔아도 터미널이 그 폰트를
쓰도록 설정하지 않으면 똑같이 두부입니다.** 이 리포가 Windows Terminal 설정까지
자동으로 건드리는 이유가 이것입니다 — 자세한 건 [comparison.md](comparison.md)를 보세요.

## 설치 스크립트가 하는 일

[`install.ps1`](../install.ps1)은 위 4층을 순서대로 조립합니다.

| 단계 | 하는 일 | 왜 이 순서인가 |
|---|---|---|
| 1 | winget으로 패키지 설치 | 나머지가 전부 여기에 의존 |
| 2 | Nerd Font 설치 | 6단계에서 폰트 이름을 지정해야 하므로 먼저 |
| 3 | PowerShell 모듈 | |
| 4 | oh-my-posh 테마 배치 + **캐시 비우기** | 캐시를 안 비우면 새 테마가 무시됨 |
| 5 | PowerShell 프로필 배치 | |
| 6 | Windows Terminal 설정 **병합** | 덮어쓰기가 아니라 병합 |
| 7 | 검증 | 실제로 로드되는지 확인 |

각 단계에서 밟기 쉬운 지뢰는 [troubleshooting.md](troubleshooting.md)에 정리해뒀습니다.
